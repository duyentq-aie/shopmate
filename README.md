# ShopMate

ShopMate is an AI sales assistant for e-commerce: a retrieval-augmented (RAG) agent that answers shopper questions grounded in a store's product catalog and order data. It runs as its own service next to an open-source Saleor stack and talks to Saleor only through its GraphQL API. This repository currently holds the Phase 1 groundwork (a reproducible local Saleor environment and a smoke test) and the Phase 2 data foundation (a synthetic Vietnamese catalog, test orders, policy documents, a draft golden evaluation set and a read-only Saleor client); the AI service itself is not built yet.

## Layout

| Path | Purpose |
|---|---|
| `app/` | The ShopMate service. So far: data schemas, shop constants, the read-only Saleor client (`app/saleor/readonly_client.py`) and retrieval (`app/retrieval/`: bge-m3 embeddings, Qdrant index, dense/hybrid search, and the diacritic-folded lexical vector with its two Phase 4 configurations). |
| `docker-compose.yml` | ShopMate's own services (Qdrant), separate from Saleor's. |
| `app/tracing.py`, `app/pipeline.py` | Request tracing (one JSON line per request in git-ignored `logs/traces.jsonl`, see `docs/DECISIONS-tracing.md`) and the request path router → extractor → retrieval it traces. |
| `app/monitor.py`, `dashboard/` | The local trace monitor: `uv run python -m app.monitor` serves `dashboard/index.html` at `http://127.0.0.1:8765/monitor/` and the tail of `logs/traces.jsonl` at `/monitor/api/traces`. Read-only, loopback only, no token mode (`docs/DECISIONS-monitor.md`). |
| `app/agent/` | Phase 6 (in progress): the bounded conversation agent, a LangGraph workflow with fixed bounds on every loop. Design: `docs/AGENT-DESIGN.md`; decisions and pre-registered rules: `docs/DECISIONS-phase6.md`. |
| `app/llm/`, `prompts/` | Phase 5: Gemini client with free-tier guards (cache, rate limit, daily ceiling), the router and the filter extractor, and their versioned prompts. |
| `data/index/manifest.json` | Lineage of the current vector index and the collection evaluation runs against (model revision, lexical config, counts, vector digest, source hashes). |
| `data/seed/` | Synthetic catalog (`catalog.vi.json`) and test orders (`orders.vi.json`), versioned. |
| `data/policies/` | Policy documents of the fictional shop (đổi trả, vận chuyển, bảo hành), with numbered clauses. |
| `eval/golden/` | Golden evaluation set (`golden.vi.json`), its schema, drafting and validation scripts. |
| `eval/` | Retrieval evaluation: runner (`run_retrieval_eval.py`), metrics, Phase 3B comparison, and the Phase 4 experiment 1 rule (`exp1_rule.py`), perturbation set (`perturbation/`) and comparison (`compare_exp1.py`). Results in `eval/results/`. |
| `scripts/` | Generators, seeders for Saleor channel `vn`, the drift report and the Phase 1 smoke test. `scripts/demo_requests.py` runs ten hand-written questions through the pipeline and writes their traces (`uv run python -m scripts.demo_requests`, offline from the cache; `--live` fetches missing answers within the free-tier guards). |
| `tests/` | `uv run pytest`: unit tests, no services. `uv run pytest -m integration`: live Qdrant, model and Saleor. `scripts/test_all.sh` runs both. |
| `docs/SETUP.md` | How the local environment was set up, Saleor app permissions, seeding commands. |
| `.env.example` | Configuration template (placeholders only). |

## Data: all synthetic

**All catalog, order and customer data in this repository is synthetic.** It is generated by code with a fixed random seed (`scripts/generate_catalog.py`, `scripts/generate_orders.py`), without any LLM, and describes a fictional shop, "ShopMate Fashion". Customer emails use the reserved `example.com` domain; addresses are made up. The policy documents are fictional too.

Catalog model, a deliberate simplification: **one product = one variant = one SKU**. `màu sắc` (color) and `chất liệu` (material) are single-value attributes; `kích cỡ` (size) is a multiselect of the sizes the product is *available in*, so a size filter means "products whose available sizes include X". **There is no per-size stock**: a product has one stock number for all its sizes. Product images are not seeded.

## Python environment

The project uses a project-local Python 3.12 managed by [uv](https://docs.astral.sh/uv/) (not the system Python 3.14):

```bash
uv sync          # creates .venv with Python 3.12 and the locked dependencies
uv run pytest    # runs all tests; no Saleor stack or token needed
```

## Quick check

With the local Saleor stack running (see [`docs/SETUP.md`](docs/SETUP.md)):

```bash
uv run python -m scripts.check_saleor --wait 60   # reads SALEOR_RUNTIME_TOKEN from .env
```

## Ownership

ShopMate is my own AI service. It runs alongside Saleor as a separate process and is not a fork or modification of it. All code in this repository is mine.

The Saleor stack used for local development is third-party infrastructure that lives outside this repository (in sibling folders `saleor-platform/` and `storefront/`). **No Saleor code is part of this repo**, with one exception: Saleor's GraphQL schema (SDL) is kept, unmodified and with its BSD-3-Clause license, as a test fixture in `tests/fixtures/` so queries can be validated offline. The stack is cloned and run as-is, and each project keeps its own license:

- [saleor-platform](https://github.com/saleor/saleor-platform): BSD-3-Clause
- [Saleor storefront](https://github.com/saleor/storefront): FSL-1.1-ALv2 (Functional Source License 1.1, with an Apache 2.0 future license)
